# Προδιαγραφές Διεπαφών REST API — Έξυπνοι Ανελκυστήρες (Destination Dispatch)

**Ομάδα:** JAVENGERS  
**Έκδοση API:** `v1`  
**Μορφή Δεδομένων:** `application/json; charset=UTF-8`  
**Προεπιλεγμένη Τοπική Διεύθυνση Κεντρικού Συστήματος:** `http://localhost:8080`

Το παρόν έγγραφο καθορίζει τις τυποποιημένες προδιαγραφές των REST APIs για την επικοινωνία μεταξύ των τεσσάρων ανεξάρτητων υποσυστημάτων του έργου **«Έξυπνοι Ανελκυστήρες» (Destination Dispatch)**:

1. **Διεπαφή Χρήστη (User Interface)** — Οθόνη/τερματικό ορόφου για την υποβολή αιτημάτων επιβατών.
2. **Κεντρικό Σύστημα Ελέγχου (Central Control System)** — Ο «εγκέφαλος» του συστήματος που εκτελεί τον αλγόριθμο ανάθεσης (dispatching).
3. **Σύστημα Ελέγχου Ανελκυστήρα (Elevator Control System)** — Διαχείριση κίνησης, στάσεων, θυρών και τηλεμετρίας κάθε ανελκυστήρα.
4. **Σύστημα Δοκιμών και Αξιολόγησης (Evaluation System)** — Παραμετροποίηση, εκτέλεση σεναρίων προσομοίωσης και συλλογή μετρικών απόδοσης (KPIs).

Ο σχεδιασμός καλύπτει τις προδιαγραφές κλίμακας του έργου (**2–20 ανελκυστήρες** και **3–200 όροφοι**) και διασφαλίζει πλήρη **διαλειτουργικότητα** με υποσυστήματα άλλων ομάδων.

## 1. Συνοπτικός Πίνακας Διεπαφών (Endpoints Overview)

| Υποσύστημα (Καλών) | Λειτουργία | HTTP Method | Path | Περιγραφή |
| :--- | :--- | :---: | :--- | :--- |
| **Διεπαφή Χρήστη** | Κλήση/Αίτημα για ανελκυστήρα | `POST` | `/api/v1/central/requests` | Καταγραφή αιτήματος επιβάτη και επιστροφή του ανατιθέμενου ανελκυστήρα |
| **Κεντρικό Σύστημα Ελέγχου** | Εντολή Κίνησης | `POST` | `/api/v1/elevators/{elevatorId}/stops` | Ανάθεση στάσης στον επιλεγμένο ανελκυστήρα (`PICK_UP` ή `DROP_OFF`) |
| **Κεντρικό / Αξιολόγηση** | Τηλεμετρία Ανελκυστήρα | `GET` | `/api/v1/elevators/{elevatorId}/status` | Συνεχής παρακολούθηση ανελκυστήρα (όροφος, κίνηση, κατάσταση θυρών, φορτίο) |
| **Σύστημα Αξιολόγησης** | Διαμόρφωση Παραμέτρων | `GET` | `/api/v1/central/config` | Ανάγνωση παραμέτρων διαμόρφωσης κτιρίου και ανελκυστήρων |
| **Σύστημα Αξιολόγησης** | Εκκίνηση Σεναρίου Προσομοίωσης | `POST` | `/api/v1/evaluation/scenarios` | Έναρξη καταγραφής χρόνων και απόδοσης για σενάριο προσομοίωσης |
| **Σύστημα Αξιολόγησης** | Αποτελέσματα Σεναρίου Προσομοίωσης | `GET` | `/api/v1/evaluation/scenarios/{scenarioId}/metrics` | Εξαγωγή τελικών στατιστικών απόδοσης (KPIs) |
| **Σύστημα Αξιολόγησης** | Επαναφορά Συστήματος | `POST` | `/api/v1/evaluation/reset` | Επαναφορά κατάστασης και εκκαθάριση μνήμης του συστήματος |

## 2. Ονοματολογία & Συμβάσεις Δεδομένων

Για την απρόσκοπτη διαλειτουργικότητα όλων των υποσυστημάτων, υιοθετούνται οι παρακάτω τυποποιημένες συμβάσεις (ευθυγραμμισμένες με τα DTOs και τα enums του κώδικα):

* **Αναγνωριστικό Ανελκυστήρα (`elevatorId`):** `String`. Γράμματα του λατινικού αλφαβήτου από `"A"` έως `"T"` (καλύπτοντας από 2 έως 20 ανελκυστήρες).
* **Αρίθμηση Ορόφων (`floor` / `sourceFloor` / `destinationFloor` / `targetFloor`):** `Integer`. Το ισόγειο αναπαρίσταται με `0`. Αποδεκτό εύρος τιμών: `0` έως `200` (καλύπτοντας την απαίτηση για 3–200 ορόφους).
* **Κατεύθυνση Κίνησης (`direction` — `Direction`):** `String` με αποδεκτές τιμές:
  * `"UP"` — Κίνηση προς τα πάνω
  * `"DOWN"` — Κίνηση προς τα κάτω
  * `"IDLE"` — Ακινητοποιημένος / σε αναμονή
* **Κατάσταση Θυρών (`doorState` — `DoorState`):** `String` με αποδεκτές τιμές:
  * `"OPEN"`
  * `"CLOSED"`
  * `"OPENING"`
  * `"CLOSING"`
* **Κατάσταση Λειτουργίας (`operatingState` — `OperatingState`):** `String` με αποδεκτές τιμές:
  * `"NORMAL"` — Κανονική λειτουργία
  * `"OVERLOAD"` — Υπέρβαση μέγιστου επιτρεπτού βάρους
  * `"OUT_OF_SERVICE"` — Εκτός λειτουργίας / συντήρηση
  * `"EMERGENCY_STOP"` — Έκτακτη διακοπή λειτουργίας
* **Τύπος Στάσης (`stopType` — `StopType`):** `String` με αποδεκτές τιμές:
  * `"PICK_UP"` — Στάση επιβίβασης επιβάτη
  * `"DROP_OFF"` — Στάση αποβίβασης επιβάτη
* **Τύπος Σεναρίου Κυκλοφορίας (`passengerTrafficScenario`):** `String` με ενδεικτικές τιμές:
  * `"MORNING_UP_PEAK"` — Πρωινή αιχμή (μετακίνηση κυρίως από το ισόγειο προς τους ορόφους)
  * `"EVENING_DOWN_PEAK"` — Απογευματινή αιχμή (μετακίνηση κυρίως από τους ορόφους προς το ισόγειο)
  * `"INTERFLOOR"` — Ενδοκτιριακή κυκλοφορία μεταξύ ορόφων
  * `"RANDOM"` — Τυχαία κατανομή αιτημάτων
* **Μορφή & Headers:** Όλα τα αιτήματα με σώμα (body) και όλες οι απαντήσεις χρησιμοποιούν `Content-Type: application/json`.

## 3. Αναλυτική Προδιαγραφή Endpoints

### 3.1. Διεπαφή Χρήστη προς Κεντρικό Σύστημα

#### Κλήση / Αίτημα για Ανελκυστήρα
* **Endpoint:** `POST /api/v1/central/requests`
* **Σκοπός:** Υποβολή αιτήματος μετακίνησης για **έναν (1) επιβάτη** από τον όροφο αφετηρίας προς τον όροφο προορισμού. Το Κεντρικό Σύστημα εκτελεί τον αλγόριθμο Destination Dispatch και επιστρέφει το αναγνωριστικό του ανελκυστήρα που ανατέθηκε.
* **Αρχιτεκτονική Σημείωση:** Κάθε αίτημα αντιστοιχεί αυστηρά σε έναν επιβάτη. Σε περίπτωση ομάδας ατόμων, η Διεπαφή Χρήστη αποστέλλει ξεχωριστό αίτημα για κάθε επιβάτη, ώστε το Κεντρικό Σύστημα να διαχειρίζεται δυναμικά τη χωρητικότητα κάθε ανελκυστήρα.
* **Κανόνες Επικύρωσης (Validation):**
  * Το σώμα του αιτήματος δεν πρέπει να είναι κενό και πρέπει να περιέχει έγκυρο JSON.
  * `0 <= sourceFloor <= 200` και `0 <= destinationFloor <= 200` (εντός των ορίων του κτιρίου).
  * `sourceFloor != destinationFloor` (δεν επιτρέπεται κλήση στον ίδιο όροφο).

**Request Body (`PassengerRequest`):**
```json
{
  "sourceFloor": 0,
  "destinationFloor": 5
}
```

**Success Response (`200 OK` — `ElevatorResponse`):**
```json
{
  "status": 200,
  "assignedElevator": "B"
}
```

**Error Response (`400 Bad Request`):**
```json
{
  "error": "Source and destination floors cannot be the same. Please use your feet."
}
```

**Αναμενόμενα HTTP Status Codes:**
| Status Code | Περιγραφή |
| :---: | :--- |
| `200 OK` | Επιτυχής καταγραφή αιτήματος και ανάθεση ανελκυστήρα |
| `400 Bad Request` | Κενό/άκυρο JSON, όροφος εκτός ορίων (`< 0` ή `> 200`), ή `sourceFloor == destinationFloor` |
| `405 Method Not Allowed` | Χρήση HTTP μεθόδου διαφορετικής από `POST` |

### 3.2. Κεντρικό Σύστημα προς Σύστημα Ελέγχου Ανελκυστήρα

#### Εντολή Κίνησης (Ανάθεση Στάσης)
* **Endpoint:** `POST /api/v1/elevators/{elevatorId}/stops`
* **Σκοπός:** Προσθήκη νέας στάσης επιβίβασης (`PICK_UP`) ή αποβίβασης (`DROP_OFF`) στο δρομολόγιο ενός συγκεκριμένου ανελκυστήρα.
* **Path Parameters:**
  * `elevatorId` (`String`, υποχρεωτικό): Το αναγνωριστικό του επιλεγμένου ανελκυστήρα (π.χ. `B`).

**Request Body (`StopRequest`):**
```json
{
  "targetFloor": 5,
  "stopType": "DROP_OFF"
}
```
*(Σημείωση: Το πεδίο `stopType` λαμβάνει τιμές `"PICK_UP"` ή `"DROP_OFF"`. Σε απλοποιημένες κλήσεις μπορεί να παραληφθεί αν η στάση αντιμετωπίζεται ενιαία από τον ελεγκτή.)*

**Success Response (`200 OK` — `StopResponse`):**
```json
{
  "elevatorId": "B",
  "status": "ACCEPTED"
}
```

**Error Response (`400 Bad Request` / `404 Not Found`):**
```json
{
  "error": "Elevator with ID 'Z' was not found."
}
```

**Αναμενόμενα HTTP Status Codes:**
| Status Code | Περιγραφή |
| :---: | :--- |
| `200 OK` | Η εντολή στάσης έγινε αποδεκτή και προστέθηκε στο δρομολόγιο |
| `400 Bad Request` | Μη έγκυρο JSON, όροφος εκτός ορίων κτιρίου ή μη αποδεκτός `stopType` |
| `404 Not Found` | Δεν βρέθηκε ανελκυστήρας με το δοθέν `elevatorId` |
| `405 Method Not Allowed` | Χρήση HTTP μεθόδου διαφορετικής από `POST` |

### 3.3. Σύστημα Ελέγχου Ανελκυστήρα (Τηλεμετρία / Polling)

#### Λήψη Κατάστασης Ανελκυστήρα
* **Endpoint:** `GET /api/v1/elevators/{elevatorId}/status`
* **Σκοπός:** Παρέχει σε πραγματικό χρόνο την τρέχουσα τηλεμετρία ενός ανελκυστήρα προς το Κεντρικό Σύστημα (για τη λήψη αποφάσεων dispatching) και προς το Σύστημα Αξιολόγησης (για την παρακολούθηση της προσομοίωσης).
* **Path Parameters:**
  * `elevatorId` (`String`, υποχρεωτικό): Το αναγνωριστικό του ανελκυστήρα (π.χ. `A`, `B`).

**Request Body:** Κανένα (`GET` request).

**Success Response (`200 OK` — `ElevatorStatus`):**
```json
{
  "elevatorId": "B",
  "operatingState": "NORMAL",
  "currentFloor": 3,
  "direction": "UP",
  "doorState": "CLOSED",
  "currentWeightKg": 320.5,
  "nextStops": [5, 8]
}
```

**Αναμενόμενα HTTP Status Codes:**
| Status Code | Περιγραφή |
| :---: | :--- |
| `200 OK` | Επιτυχής επιστροφή της τρέχουσας κατάστασης του ανελκυστήρα |
| `404 Not Found` | Δεν βρέθηκε ανελκυστήρας με το δοθέν `elevatorId` |
| `405 Method Not Allowed` | Χρήση HTTP μεθόδου διαφορετικής από `GET` |
| `500 Internal Server Error` | Εσωτερικό σφάλμα ανάκτησης κατάστασης (π.χ. μη αρχικοποιημένη κατάσταση ανελκυστήρα) |

### 3.4. Σύστημα Αξιολόγησης προς Κεντρικό Σύστημα

#### 3.4.1. Διαμόρφωση Παραμέτρων Κτιρίου
* **Endpoint:** `GET /api/v1/central/config`
* **Σκοπός:** Ανάκτηση των ενεργών παραμέτρων διαμόρφωσης του κτιρίου και του στόλου ανελκυστήρων από το Κεντρικό Σύστημα, ώστε το Σύστημα Αξιολόγησης να παράγει έγκυρα σενάρια εντός των ορίων του συστήματος.

**Request Body:** Κανένα (`GET` request).

**Success Response (`200 OK`):**
```json
{
  "minFloor": 0,
  "maxFloor": 19,
  "totalFloors": 20,
  "totalElevators": 4,
  "elevatorIds": ["A", "B", "C", "D"],
  "maxWeightKg": 1000.0,
  "speedFloorsPerSecond": 1.0
}
```

**Αναμενόμενα HTTP Status Codes:**
| Status Code | Περιγραφή |
| :---: | :--- |
| `200 OK` | Επιτυχής επιστροφή των παραμέτρων διαμόρφωσης |
| `405 Method Not Allowed` | Χρήση HTTP μεθόδου διαφορετικής από `GET` |
| `500 Internal Server Error` | Αδυναμία ανάγνωσης της τρέχουσας διαμόρφωσης |

---

#### 3.4.2. Εκκίνηση Σεναρίου Προσομοίωσης
* **Endpoint:** `POST /api/v1/evaluation/scenarios`
* **Σκοπός:** Έναρξη ενός νέου σεναρίου προσομοίωσης με συγκεκριμένες παραμέτρους κτιρίου, προφίλ κυκλοφορίας και διάρκεια, ενεργοποιώντας την καταγραφή χρόνων και δεικτών απόδοσης.

**Request Body (`ScenarioRequest`):**
```json
{
  "totalElevators": 4,
  "totalFloors": 20,
  "passengerTrafficScenario": "MORNING_UP_PEAK",
  "durationMinutes": 15
}
```

**Success Response (`202 Accepted`):**
```json
{
  "scenarioId": "sim-2026-11-24-01",
  "status": "RUNNING",
  "message": "Simulation started successfully."
}
```

**Αναμενόμενα HTTP Status Codes:**
| Status Code | Περιγραφή |
| :---: | :--- |
| `202 Accepted` | Το σενάριο έγινε αποδεκτό και η προσομοίωση ξεκίνησε |
| `400 Bad Request` | Μη έγκυρες παράμετροι (π.χ. `totalElevators` εκτός `2–20`, `totalFloors` εκτός `3–200`, ή μη έγκυρη διάρκεια) |
| `405 Method Not Allowed` | Χρήση HTTP μεθόδου διαφορετικής από `POST` |
| `409 Conflict` | Υπάρχει ήδη ενεργό σενάριο προσομοίωσης σε εξέλιξη |

---

#### 3.4.3. Λήψη Αποτελεσμάτων / Μετρικών Προσομοίωσης
* **Endpoint:** `GET /api/v1/evaluation/scenarios/{scenarioId}/metrics`
* **Σκοπός:** Ανάκτηση των συγκεντρωτικών στατιστικών απόδοσης (KPIs) για ένα ολοκληρωμένο (ή εν εξελίξει) σενάριο προσομοίωσης.
* **Path Parameters:**
  * `scenarioId` (`String`, υποχρεωτικό): Το μοναδικό αναγνωριστικό σεναρίου που επιστράφηκε από το `POST /api/v1/evaluation/scenarios`.

**Request Body:** Κανένα (`GET` request).

**Success Response (`200 OK` — `MetricsResponse`):**
```json
{
  "scenarioId": "sim-2026-11-24-01",
  "status": "COMPLETED",
  "metrics": {
    "totalPassengersServed": 142,
    "averageWaitTimeSeconds": 12.5,
    "averageJourneyTimeSeconds": 38.0,
    "maxWaitTimeSeconds": 45.0,
    "overloadedRejections": 2
  }
}
```

**Αναμενόμενα HTTP Status Codes:**
| Status Code | Περιγραφή |
| :---: | :--- |
| `200 OK` | Επιτυχής επιστροφή των μετρικών απόδοσης |
| `404 Not Found` | Δεν βρέθηκε σενάριο με το δοθέν `scenarioId` |
| `405 Method Not Allowed` | Χρήση HTTP μεθόδου διαφορετικής από `GET` |

---

#### 3.4.4. Επαναφορά Συστήματος (Reset)
* **Endpoint:** `POST /api/v1/evaluation/reset`
* **Σκοπός:** Εκκαθάριση μνήμης, μηδενισμός ενεργών αιτημάτων/δρομολογίων και επαναφορά των ανελκυστήρων και των μετρητών αξιολόγησης στην αρχική τους κατάσταση, επιτρέποντας τη διαδοχική εκτέλεση ανεξάρτητων δοκιμών χωρίς επανεκκίνηση των διεργασιών.

**Request Body:** Κανένα (ή κενό αντικείμενο `{}`).

**Success Response (`200 OK`):**
```json
{
  "status": "RESET",
  "message": "System state and evaluation memory cleared successfully."
}
```

**Αναμενόμενα HTTP Status Codes:**
| Status Code | Περιγραφή |
| :---: | :--- |
| `200 OK` | Επιτυχής επαναφορά συστήματος και εκκαθάριση μνήμης |
| `405 Method Not Allowed` | Χρήση HTTP μεθόδου διαφορετικής από `POST` |
| `500 Internal Server Error` | Σφάλμα κατά την επαναφορά της κατάστασης του συστήματος |

## 4. Τυποποιημένη Διαχείριση Σφαλμάτων

Σε όλες τις περιπτώσεις σφάλματος (`4xx` και `5xx`), οι εξυπηρετητές επιστρέφουν το κατάλληλο HTTP Status Code μαζί με ένα ενιαίο JSON σώμα της μορφής:

```json
{
  "error": "Περιγραφικό μήνυμα σφάλματος"
}
```

### Σύνοψη HTTP Status Codes
* **`200 OK`**: Επιτυχής εκτέλεση αιτήματος (`GET` / `POST`).
* **`202 Accepted`**: Επιτυχής αποδοχή ασύγχρονης διεργασίας (εκκίνηση σεναρίου).
* **`400 Bad Request`**: Λανθασμένα δεδομένα εισόδου, μη έγκυρο JSON ή παραβίαση επιχειρησιακών κανόνων (π.χ. άκυρος όροφος).
* **`404 Not Found`**: Ο ζητούμενος πόρος (`elevatorId` ή `scenarioId`) δεν υπάρχει.
* **`405 Method Not Allowed`**: Η HTTP μέθοδος δεν υποστηρίζεται από το συγκεκριμένο endpoint.
* **`409 Conflict`**: Σύγκρουση κατάστασης (π.χ. προσπάθεια εκκίνησης νέου σεναρίου ενώ τρέχει ήδη άλλο).
* **`500 Internal Server Error`**: Απρόσμενο εσωτερικό σφάλμα του εξυπηρετητή.
